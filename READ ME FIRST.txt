  !!  NO GUARANTEE  --  BACK UP FIRST  !!

  This tool comes with NO GUARANTEE that the saves it produces are stable or
  free of corruption. USE IT AT YOUR OWN RISK, and ALWAYS keep a backup of any
  save you care about before touching it.

  The save format was reverse-engineered, not documented. It is verified as far
  as it can be -- a real Xbox 360 save survives a full round trip bit-identical
  -- but the game's field types are only known for the parts that real saves
  happened to exercise. A field shape nobody has seen yet may still convert
  wrongly, and a bad conversion can look perfectly fine for hours of play before
  something turns out to be missing or nonsensical.

  Convert into a SPARE SLOT. Never over your only copy.


--------------------------------------------------------------------------------
  WHAT IT DOES
--------------------------------------------------------------------------------

  Moves a LEGO Dimensions save between Xbox 360 (xenia), PS3 (RPCS3),
  PS4 (shadPS4) and Wii U (Cemu). Any direction, all files at once.

  It also converts out to Recomp (ReXGlue), the static recompilation.

  Windows only. Single .exe, nothing to install.


--------------------------------------------------------------------------------
  HOW TO USE IT
--------------------------------------------------------------------------------

  1. Back up the save you are converting FROM, and the slot you are converting
     INTO. Copy both folders somewhere safe. Do this first, not later.

  2. Run DimensionsSaveConverter.exe.

  3. Source save folder  -> the folder holding the save you want to convert,
     or any folder above it. The tool searches downwards for saves, on
     every platform, and shows what it found underneath.

     If it finds MORE THAN ONE save it stops and lists the full path of
     each. Nothing is converted until you point it at exactly one of them.
     It will not guess which save you meant.

  4. Target platform     -> the emulator you want to play it on.

  5. Output folder       -> an empty folder. Must not be the source folder.

  6. Press Convert.


--------------------------------------------------------------------------------
  WII U / CEMU SAVES ARE BURIED, AND SPLIT IN TWO
--------------------------------------------------------------------------------

  Cemu does not keep a Wii U save in one flat folder. It looks like this:

     save\00050000\<title id>\user\<account>\Slot1\
        GAME0, V2GAME0, DLC0 ... DLC30, OPTS0, OPTSC0, FEOPTS0
     save\00050000\<title id>\user\<account>\OPTIONS\
        GLOBAL0

  Just point the tool at any of those folders -- the dump root, the title
  folder, or Slot1 itself. It finds the slot on its own and picks up GLOBAL0
  from the OPTIONS folder next to it.

  Converting TO Wii U writes the same shape back: a Slot1\ folder next to an
  OPTIONS\ folder, ready to copy into user\<account>\.


--------------------------------------------------------------------------------
  TWO THINGS THAT WILL BITE YOU IF YOU SKIP THEM
--------------------------------------------------------------------------------

  1) CONVERT THE WHOLE SAVE, WITH EVERY DLC FILE

     Point the tool at the COMPLETE save folder -- all thirty DLC files along
     with GAME and V2GAME -- and copy ALL of the results into the target slot.

     Progress is spread across those files. Each DLC file is one world; the main
     blob only holds what is common to all of them. Convert a partial folder, or
     copy only some of the output across, and you get a save that loads but is
     missing worlds. There is nothing to gain by leaving files out.


  2) THE TARGET SLOT MUST ALREADY CONTAIN A SAVE THE GAME ITSELF MADE

     DO NOT just drop the converted folder in as a new save slot. It will not
     work.

     Instead:
        - start the game on the target emulator
        - create a new save in a spare slot
        - quit the game
        - REPLACE THE FILES INSIDE THAT SLOT with the converted ones

     Every platform stores per-slot metadata that this tool never writes. Without
     it the slot shows up empty or not at all, no matter how correct the save
     files themselves are:

        Xbox 360 (xenia)  the .header file in  Headers\<profile>\
        PS3 (RPCS3)       PARAM.SFO  and  ICON0.PNG
        PS4 (shadPS4)     the  sce_sys\  folder  (param.sfo, icon0.png)
        Wii U (Cemu)      the  meta\  folder  (meta.xml, iconTex.tga)

     So: let the game create the slot, then swap the files inside it.


--------------------------------------------------------------------------------
  WHERE SAVES USUALLY LIVE
--------------------------------------------------------------------------------

  xenia     content\<profile>\5752084B\00000001\savegame_1\
  ReXGlue   content\<XUID>\5752084B\00000001\savegame_1\
  RPCS3     dev_hdd0\home\00000001\savedata\BLES02105000\   (EU)
            dev_hdd0\home\00000001\savedata\BLUS31488\      (US)
  shadPS4   savedata\CUSA01176\Slot00\
  Cemu      <title id>\user\<account>\Slot1\


--------------------------------------------------------------------------------
  NOTES
--------------------------------------------------------------------------------

  - Converting TO Recomp (ReXGlue): point the output folder at the profile
    folder inside ReXGlue's content\ -- the one named after the XUID -- and the
    title id folder, the slot and its header are all written for you. Use the
    ReXGlue slot box to choose which slot to land in; left alone, the save
    keeps the slot and name it had under xenia.

    AIM AT A SLOT REXGLUE HAS LOADED BEFORE, and copy the result in by
    MERGING, not by deleting the slot folder first. A slot ReXGlue made but
    never committed a save to -- created, then quit before the intro cutscenes
    finished -- cannot be loaded at all. Merging also leaves that slot's own
    OPTS01 / FEOPTS01 / OPTSC01 alone, which is what you want: another
    machine's options files are what make Load Game come up empty. The
    converter never writes options into a recomp save for that reason.

    Close the game before swapping files. It rewrites the save on exit.

  - Region does not matter. It only changes the folder name (the title ID),
    never the file format. Drop the output into whichever regional folder your
    own copy uses.

  - Options files (settings, not progress) are not carried between platforms of
    different byte order. Volume, subtitles and so on will need setting again.

  - The save revision is converted for you. Wii U saves are revision 12 while
    Xbox 360, PS3 and PS4 use revision 13, and the game does NOT accept the
    wrong revision -- it shows the slot as a brand new game, however correct
    the data inside it is. The tool rewrites the save to whichever revision
    the target platform uses, so this is handled; there is nothing to set.

  - Options files cannot cross a revision boundary (or a byte-order one). They
    are raw structs, not record streams, so they are skipped with a note in
    the log. Settings will need setting again; progress is unaffected.

  - If files already exist in the output folder they are copied into a _backup_
    subfolder first. That is a convenience, not a backup strategy. Keep your own
    copy too.
